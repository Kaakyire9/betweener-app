# Connect historical records

The [current README](../README.md) is the product entry point. All numbered reports
remain at their original paths and bytes so receipts, links and frozen packages
remain reproducible. This is a logical archive, not a move or rewrite of evidence.

## How to read the history

| Records | Subject |
| --- | --- |
| 00–16 | Original architecture, relationship remediation, implementation and M2 checks |
| 18–32 | Media Truth experiments, forensic review and offline classifier work |
| 33–38 | Revocation architecture, security contracts and End Call & Block |
| 39–43 device documents | Native-owner and retired standalone-harness preparation |
| 42–48 product documents | Product integration, staging installation and shared-push recovery |

Repeated numbers 42, 43, 44 and 46 identify different documents or a report plus its
proposal; they are not duplicate copies. Numbers were not renumbered because they
are referenced by retained evidence. The older `connect-v1-architecture-audit.md`
contains an M0-era status and is historical, not the current status page.

`offline-30`, `offline-31`, `offline-32`, `offline-34` and `offline-37` retain offline
analysis and tests. They are not imported by the current product. Do not execute
old provider runners or reuse consumed experiment approvals.

## Retired entry points

The mock app preview route and the executable standalone launcher have been retired.
Their exact source bytes and hashes are retained in [retired-code/manifest.json](retired-code/manifest.json).
The old launcher path now prints a retirement notice without device or network work.
The old staging-preview launcher remains absent.
