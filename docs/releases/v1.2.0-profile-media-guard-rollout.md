## Compatibility boundary

- Expo `runtimeVersion` uses `appVersion`; a 1.2.0 update cannot load in 1.1.1.
- Only the 1.2.0 client invokes `profile-media-guard-v1-2`.
- Existing 1.1.1 profile media remains visible and removable. Login, profile
  reads, chat, and non-media profile edits remain available. New avatar/gallery
  references from legacy public buckets are rejected because their provenance
  cannot prove server moderation. New references require an exact service-owned
  URL/object/hash approval record. A 1.1.1 user must use 1.2.0 to add or replace
  profile media after the blocker-closure migration reaches that environment.
- Do not add this migration to `v1.1.1_production_health.sql`.

## Device acceptance cases

- Avatar: one clear face is accepted.
- Avatar: no face or multiple faces is rejected immediately.
- Avatar and gallery: explicit nudity, sexual content, unsafe QR destinations, contact details,
  off-platform promotion, advertising, violence, and hate are rejected immediately.
- Gallery: a face is not required.
- Incidental non-promotional writing and clothing logos are allowed.
- Provider timeout returns a retry message and leaves the current profile unchanged.
- Rejected images do not create an admin-review item.

## Operational rollback

If the 1.2.0 media path is unhealthy, stop the 1.2.0 rollout or force an app update.
Do not route 1.2.0 uploads back through the public legacy upload bucket. The 1.1.1
binary remains on its unchanged legacy contract throughout.
