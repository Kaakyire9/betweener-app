# Betweener 1.2.0 chat hardening roadmap

Status: deferred until the remaining master prompts are implemented and audited.

This document preserves the chat/messages audit roadmap for Betweener 1.2.0.
Production version 1.1.1 has active users and must remain compatible throughout
development, deployment, rollout, and rollback.

## Production compatibility contract

- Treat the installed 1.1.1 client contract as immutable until an explicit
  retirement gate is approved.
- Keep client-only 1.2.0 behavior on the 1.2.0 Expo runtime. Do not publish a
  1.2.0 update to the 1.1.1 runtime.
- Use expand-and-contract database migrations: nullable/additive schema first,
  new versioned RPCs second, 1.2.0 client adoption third, destructive cleanup
  only after 1.1.1 retirement.
- Do not remove or change RPC signatures, columns, storage paths, policies, or
  Edge Function request modes used by 1.1.1.
- Treat Edge Functions and database migrations as shared production surfaces;
  they require explicit 1.1.1 compatibility tests even when only 1.2.0 uses the
  new feature.
- Run the 1.1.1 production health gate before and after every backend deploy.
- Deploy migrations before compatible Edge Functions, then release the 1.2.0
  client gradually with rollback and observability ready.

## Deferred P0 security work

1. Replace broad authenticated `messages` INSERT/UPDATE access with narrow,
   versioned send, receipt, edit, delete, and live-location RPCs while preserving
   a compatible 1.1.1 path until retirement.
2. Make message identity, participants, type, creation time, attachment identity,
   and encryption metadata immutable at the database boundary.
3. Close direct-insert moderation bypasses and add hostile-client RLS tests.
4. Purge all user-scoped chat snapshots on sign-out, account switch, and account
   deletion.
5. Separate push submission from recipient-device delivery acknowledgement.
6. Make the product privacy model explicit: moderation-first server-readable
   messaging, or audited end-to-end encryption with a protocol designed for
   multi-device use.

## Deferred P1 architecture and privacy work

1. Decompose `ChatScreen` into thread, composer, attachment, voice, location,
   date-plan, message-action, and viewer controllers/components.
2. Introduce conversations and conversation-members as the durable server model
   before groups or multi-device receipt fan-out.
3. Add online/last-seen/read-receipt privacy controls, disappearing messages,
   and per-chat biometric lock.
4. Define encrypted backup, restore, account recovery, and device-transfer flows.
5. Complete video/audio/document inspection or retain and communicate their
   `REPORT_ONLY` status.

## Deferred P2 advanced-messenger work

1. If required by product strategy, adopt an audited E2EE protocol with
   per-device identities, verification, key-change warnings, and recovery.
2. Prioritize 1:1 voice/video calling and linked devices for the dating journey.
3. Add storage management, richer link previews, forwarding/sharing, and richer
   GIF/sticker discovery.
4. Add groups only if the product strategy requires them.

## Prompt 4 release gate: grouped media albums

Implementation status (2026-09-19): client, outbox, cancellation RPC expansion,
Edge Function handling, and automated regression coverage are complete locally.
Production deployment remains gated on the 1.1.1 pre/post health checks and the
production-compatible staging device matrix in `docs/chat-media-albums-prompt4.md`.

Do not mark Prompt 4 complete until:

- mixed image/video uploads work in every selection order;
- active per-item and whole-album cancellation is reachable and race-safe;
- real per-item progress is persisted/rendered;
- required restart, cancellation, response-loss, realtime-order, offline,
  expired-URL, missing-cache, and mixed-orientation scenarios have executable
  tests rather than documentation-only checks;
- the 1.1.1 compatibility suite and production health gate pass before and after
  backend deployment;
- migrations, Edge Function, client rollout, observability, and rollback are
  rehearsed in production-compatible staging.
