# Betweener 1.2.0 durable mutation rollout

This rollout keeps the global Sync Activity UI removed. Recovery remains contextual and automatic.

## Deployment order

1. Apply `20260918120000_idempotent_app_mutation_receipts.sql` to staging.
2. Run `supabase/verification/v1.2.0_offline_mutation_health.sql`; the final row must be healthy.
3. Deploy the v1.2.0 staging backend/functions already required by the release.
4. Install a fresh v1.2.0 test build and complete the device matrix below.
5. Promote migrations before publishing the v1.2.0 client. Do not publish a client first.

The client has missing-RPC fallbacks for compatibility, but the v1.2.0 release gate requires the
idempotency migration. The fallback is not the target production architecture.

## Device matrix

Run on iOS and Android with two different accounts on the same device:

- Queue an action offline, sign out, sign in as the other account, and confirm no action crosses accounts.
- Create a text Moment, media Moment, Moment comment, and Circle comment while reconnecting mid-request.
- Send a gift and start a boost while toggling connectivity immediately after submission.
- Edit profile interests, avatar/gallery media, and guarded profile text during a network interruption.
- Add/remove a chat reaction offline, then reconnect.
- Force-close after each optimistic action, reopen, and confirm one server result and correct local state.
- Leave one mutation in retry backoff and confirm an unrelated action completes without waiting for it.

Expected behavior:

- At most one server object or paid/premium action per submission.
- No technical queue screen or raw database error is shown.
- Terminal failures restore authoritative server state and show contextual copy only where relevant.
- Chat messages continue to use the existing SQLite outbox and are not moved to the shared queue.

## Observability

- `offline_mutation_recovered_after_retry` records successful recovery after retry.
- `offline_mutation_terminal_failure` records exhausted/terminal outcomes without member content.
- `offline_mutation_drain` records unexpected worker failures.
- Idempotency receipts contain only operation metadata and minimal entity identifiers and expire after 35 days.

## Rollback

The migration is additive. If the v1.2.0 client must be rolled back, leave the receipt table and RPCs in
place while older clients drain. Disable only the scheduled receipt cleanup if investigating an incident;
do not drop receipts or wrappers during active retries.
