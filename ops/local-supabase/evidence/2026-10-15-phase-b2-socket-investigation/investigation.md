The confirmed cause is in the probe client: premature `socat` termination on stdin EOF, followed by incomplete handling of Docker's chunked response and greedy selection of nested JSON keys. The exact Docker Desktop component that emitted the original HTTP 500 cannot be recovered because the original probe retained only its status line, but the same mounted socket and request return HTTP 200 after the client-lifetime correction. No current daemon-side or policy failure was found.

The 500 status line was read from `socat` connected directly to the mounted socket and was not generated by the mock suite or HAProxy. It is evidence of an HTTP response through the mounted Docker Desktop socket proxy, but the missing headers/body mean the original evidence alone cannot attribute it to the daemon.

`printf` necessarily reached EOF immediately after writing the request. The original `socat - UNIX-CONNECT:...` had neither `ignoreeof` nor a drain/inactivity timeout, so EOF occurred before response completion and could terminate the socket side. There was no explicit write-side half-close that preserved the read side.

The temporary container required force removal because PowerShell treated the container's stderr as a terminating native-command error and cancelled `docker run`'s attach/wait context before `--rm` completed. The `finally` cleanup raced the daemon's automatic removal, found the exited container, removed it, and verified absence. Docker's WSL2 log records the wait-context cancellation at `13:23:11.218088028Z` and explicit removal at `13:23:11.896477151Z`.

## Mock proof and minimal corrections

A delayed Unix-socket mock received the exact request hex above on both paths:

```text
legacy: exit=0, response bytes=empty, stderr=empty
EOF-safe: exit=0, complete HTTP 200 chunked response, stderr=empty
```

The one changed transport factor was `socat -T 4 STDIO,ignoreeof`, still wrapped in the existing five-second hard timeout. This prevents stdin EOF from terminating the response side and adds a four-second inactivity bound.

Docker returns chunked responses on this socket. The probe now removes chunk framing before validating the ping body and parsing JSON. The original greedy `sed` expression could select nested `ID` and `Version` fields; it was replaced with a top-level JSON string extractor. The mock includes later decoy `ID`, `Name`, and `Version` values and verifies selection of the intended top-level fields.

The matching raw-request test harness now uses `STDIO,ignoreeof`. The complete 41-case socket-free proxy suite passed after this change, including temporary-resource cleanup. The full corrected probe also passed the delayed chunked mock for exact `/_ping`, `/version`, and `/info` request bytes and identity output.

See `probe-fix.diff` in this directory for the existing-file changes. New diagnostic fixtures are reviewable under `ops/local-supabase/tests/vector-docker-api-proxy/`.
